## 1. 用户故事

### 1.1 教师（teacher）—— 教学辅助场景

- **T-01** 作为教师，我可以上传教案文件（TXT / MD / ZIP 批量），系统自动解析出 concepts / difficulties / learning_path
- **T-02** 作为教师，我可以用对话方式操作工作台（建班 / 建课 / 建学生 / 导入名单 / 智能导入资料），所有写操作都有"二次确认"卡片
- **T-03** 作为教师，我可以看到班级共性错误 TOP 与教学建议（ReflectorAgent 输出）
- **T-04** 作为教师，我可以**在线配置 LLM**（BaseURL / APIKey / Model），不需重启服务
- **T-05** 作为教师，我可以看到全班 SQL 代码错误 TOP10（**新增** —— 来自 CodeReviewAgent 聚合）
- **T-06** 作为教师，我可以一键导出班级报告（PDF 友好结构）

### 1.2 学生（student）—— 个性化学习 + 代码审查场景

- **S-01** 作为学生，我可以分步提交作业（"先说想法 → 再举例子 → 最后检查"三阶段），每步独立评估
- **S-02** 作为学生，提交答案后**系统不直接给标准答案**，而是按我的信任分级提供不同深度引导（locked 只追问 → hint 提示 → partial 部分 → explain 完整）
- **S-03** 作为学生，我可以在自由问答场景提问，AI 以苏格拉底式追问引导我自主思考
- **S-04** 作为学生，我可以**粘贴代码并选择语言（SQL / Python）** 让代码审查 Agent 帮我检查语法 / 风格 / 安全 / 逻辑问题（**新增**）
- **S-05** 作为学生，我能看到信任分时序图与历史评估，知道自己哪些点反复错
- **S-06** 作为学生，代码审查的反馈是"指出问题 + 方向性提示"，**不会直接给我修正后的代码**（守住"不泄题"原则）

### 1.3 管理员（admin）—— 组织管理场景

- **A-01** 作为管理员，我可以管理学校 / 班级 / 课程 / 用户的全生命周期
- **A-02** 作为管理员，我可以看全局 Dashboard（总学生数 / 总课数 / 错误率 / LLM 用量）
- **A-03** 作为管理员，我可以看全系统审计日志（含每次代码审查的提交记录）

## 2. 功能列表

### 2.1 核心教学功能

| 模块 | 功能 | 说明 |
|------|------|------|
| 教案管理 | 教案上传与解析 | TeacherAgent 自动提取 concepts / difficulties / learning_path |
| 教案管理 | 智能导入（对话区挂文件） | 意图分类：lesson / homework / outline / noise（名单/大纲被跳过） |
| 教案管理 | RAG 检索 | 关键词匹配教案库，加权评分（标题 60 + 概念 45 + 内容 35） |
| 名单管理 | 批量导入 | TXT / CSV 一键建班 + 建号；返回 created/failed 明细 |
| AI 辅导 | TutorAgent 苏格拉底 | `enforceQuestionOnly` 守门；**只提问不回答** |
| AI 辅导 | 信任分门控 | 4 级策略：locked（只追问）→ hint（给提示）→ partial（部分）→ explain（完整） |
| AI 辅导 | page_context 机制 | 教练能"看见"学生当前题干 / 阶段 / 草稿，引导不空泛 |
| 学生画像 | 持久化 | knowledge_weakness / common_errors / thinking_style / trust_score |
| 分步作业 | 三阶段 | "先说想法 → 再举例子 → 最后检查"，每步独立评估 |
| 分步作业 | 自动生成 | AI 根据教案知识点自动生成三阶段作业 |
| 学习评估 | 7 维评分 | understanding / thinking_depth / reflection / q_quality / e_quality / r_depth / really_understood |
| 教学分析 | 班级报告 | ReflectorAgent 聚合共性 + 教学建议 |

### 2.2 **新增：代码审查功能（S-Code 系列）**

| 模块 | 功能 | 说明 |
|------|------|------|
| **CR-01** | SQL 代码审查 | 沙盒执行（`:memory:` SQLite + 事务 ROLLBACK） + 风格检查（SELECT * / DELETE 无 WHERE / 关键字大写等） |
| **CR-02** | Python 代码审查 | 静态启发式（缩进 / 冒号 / 裸 except / import * / print 无 return）；**不执行用户代码** |
| **CR-03** | LLM 增强 | LLM 在启发式结果上**只补充逻辑/性能/可读性问题**；`sanitizeNoLeak` 防完整 SQL/Python 漏出 |
| **CR-04** | 可扩展架构 | `CodeReviewer` 接口 + 注册表 + `CodeReviewerFunc` 适配器；新语言只需 1 个文件 + 1 行注册 |
| **CR-05** | 前端 UI | 学生端"代码审查"场景：语言下拉 + 代码编辑 + 题目/Schema 输入 + 报告卡（分数 / 问题 / 苏格拉底式提示） |
| **CR-06** | 信任分联动 | 审查时注入当前学生 trust_score；高信任可获得更细提示，低信任只指方向（**实现中**，第一版已接审计） |
| **CR-07** | 审计 + 班级聚合 | 学生每次提交都进审计流；教师端可看"SQL 错误 Top 10"（**Sprint 2**） |

### 2.3 平台功能

| 模块 | 功能 |
|------|------|
| 认证授权 | 用户登录 / Bearer Token / RBAC 三角色 / 多端同账号 |
| 数据隔离 | 学校-班级-课程-用户；教师/学生只看到自己数据 |
| 存储引擎 | `EDU_STORAGE_DRIVER=json` 或 `sqlite`，运行时切换 |
| 系统配置 | LLM 在线配置（BaseURL / APIKey / Model）+ 连通性测试 |
| 审计日志 | 全操作审计追踪 |
| 健康检查 | `GET /healthz` |
| 容器化 | Docker / Docker Compose / 单 exe 桌面版 |

### 3.2 **新增：CodeReview 实体（设计为 HomeworkAttempt 扩展）**

```
┌────────────────────────────┐
│  HomeworkAttempt (扩展)     │
│────────────────────────────│
│ ...原有字段                 │
│ + review_score   int       │ ← CodeReview 评分
│ + review_issues  string    │ ← JSON: [{severity, type, line, message, suggestion}]
│ + review_lang    string    │ ← "sql" | "python"
│ + review_at      timestamp │
│ + review_llm     string    │ ← "llm_enhanced" | "heuristic_only" | "llm_failed_fallback"
└────────────────────────────┘

┌────────────────────────────┐
│  CodeReviewAttempt (新表)   │ ← 可选独立表
│────────────────────────────│
│ id             int PK      │
│ student_id     string FK   │
│ language       string      │
│ code           text        │
│ question       text        │
│ schema         text        │
│ result         string JSON │
│ score          int         │
│ created_at     timestamp   │
│ trust_at_submit int        │
└────────────────────────────┘
```

> **设计选择**：当前版本将 CodeReview 作为 `HomeworkAttempt` 的扩展字段（避免新建表增加复杂度）；如果未来要做"代码审查的独立分析"（如 SQL 错误 Top 10），再抽到 `CodeReviewAttempt` 独立表。

### 4.2 **CodeReview Agent 详细架构**

```
POST /edu/code-review (前端 → 后端)
    │
    │ { code, language, question, schema, context }
    ▼
┌─────────────────────────────────────────────────────────────┐
│  Service.CodeReview() — 调度入口                               │
└────────────────┬────────────────────────────────────────────┘
                 │
                 ▼
    ┌──── 查注册表 LookupCodeReviewer(language) ─────┐
    │                                                 │
    │  sql ──► sqlReviewer (Go struct)                 │
    │  python ──► pythonReviewer (Go struct)           │
    │  其他 ──► 400 unsupported                         │
    └────────────────┬────────────────────────────────┘
                     │
                     ▼
    ┌──── 启发式审查（必有结果）──────────────────────┐
    │  SQL:                                            │
    │   1) splitSQLStatements → 分号拆分               │
    │   2) 建表（schema 在事务外）                      │
    │   3) BEGIN / 跑用户代码 / ROLLBACK                │
    │   4) checkSQLStyle: SELECT*, DELETE 无 WHERE…   │
    │   5) scoreFromIssues(issues, executableOK)        │
    │                                                 │
    │  Python:                                          │
    │   1) checkPythonStyle: 缺冒号 / 缩进 / 裸 except  │
    │   2) scoreFromIssues                             │
    └────────────────┬────────────────────────────────┘
                     │ 启发式结果
                     ▼
    ┌──── LLM 增强（可选）──────────────────────────┐
    │  if s.agent != nil && 8 < len(code) < 6KB:     │
    │     input = 题目 + 启发式 issues + 代码 + 上下文  │
    │     prompt: "不直接给修正代码；苏格拉底式"        │
    │     → 解析 JSON → mergeIssues → 取 min(score)    │
    │     → sanitizeNoLeak (守门)                     │
    │  else:                                          │
    │     return heuristic only                       │
    └────────────────┬────────────────────────────────┘
                     │
                     ▼
    ┌──── 审计 (学生角色) ─────────────────────────┐
    │  AppendAudit(actor, "code_review", lang,       │
    │               "score=N issues=N llm=X")        │
    └────────────────┬────────────────────────────────┘
                     │
                     ▼
            CodeReviewResult JSON
```

## 6. 关键流程图

### 6.1 学生提交分步作业（含 CodeReview 联动）

```
学生点击「提交」
  │
  ▼
SubmitHomework(homework_id, step_index, answer)
  │
  ├─ 权限 + 班级匹配校验
  │
  ├─ EvaluatorAgent.evaluate(answer)  ──► 7 维度评分
  │
  ├─ 更新 StudentMemory (信任分 / 薄弱点 / 思维风格)
  │
  ├─ 如果 answer 含代码片段（如 SQL 练习）:
  │     ├─ 自动调 CodeReviewAgent (sql 沙盒)
  │     └─ review_score + review_issues 写入 HomeworkAttempt
  │
  ├─ TrustPolicyFor(score) → locked/hint/partial/explain
  │
  ├─ 生成引导反馈（按策略深度）
  │
  └─ 返回 GuidedHomeworkResponse { evaluation, trust, message, memory, code_review? }
```
