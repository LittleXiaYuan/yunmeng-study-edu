## 0. 摘要

本项目在 17 周开发过程中**累计使用 AI 辅助约 800+ 次交互**，主要工具为 **Claude（Cursor IDE 内置）** 与 **Mavis**（本次作业的工具链）。AI 在模板代码生成、文档撰写、调试建议等环节提供**显著加速**，但**核心教学算法（信任分计算、4 Agent Prompt 调优、SQL 沙盒设计、Python 启发式规则、SQL 注入防护）均由学生手写并经多轮课堂实测迭代**。

> **整体采纳率**：AI 生成代码总占比 ~45%，其中 ~65% 被直接采用或经小改后采纳。
> **核心架构代码采纳率 ~30%**（手写比例高）；**模板 / 文档 / 测试代码采纳率 ~80%**。

#### 典型协作片段：信任分公式

```
问：综合提问质量、解释能力、反思深度，设计 0-100 的信任分公式

AI 建议：信任分 = 提问质量×0.33 + 解释能力×0.33 + 反思深度×0.34

学生 C 修改：信任分 = 提问质量×0.45 + 解释能力×0.35 + 思维深度×0.20

修改原因：在实际课堂中，学生的"解释能力"比"反思深度"更能体现
  真正理解（反思是元认知，过度权重反而鼓励套话）。提问质量高
  通常代表主动学习。最终权重经 3 轮课堂实测后确定。
```

## 4. 关键设计决策中的 AI 参与

### 决策 1：信任分用连续分数 vs 离散分级

- **AI 建议**：连续分数（0–100 浮点）
- **学生 A 决策**：四级离散分级（locked / hint / partial / explain）
- **理由**：离散分级更符合教学直觉，教师好解释（"你得先证明你在想"）；连续分数在实际 UX 中难做反馈阈值

### 决策 2：LLM 不可用时的降级策略

- **AI 建议**：直接返回错误，让用户重试
- **学生 A 决策**：每个 Agent 实现本地启发式 fallback
- **理由**：教学系统**不能因 LLM 故障完全停止服务**；fallback 让断网 / API key 失效时核心流程仍可演示

### 决策 3：存储引擎选型

- **AI 建议**：直接上 PostgreSQL
- **学生 A 决策**：JSON 文件（dev）+ SQLite（prod），可切换
- **理由**：开发阶段 JSON 易调试；SQLite 单文件够小班教学用；避免 PG 运维成本。**PostgreSQL schema 已就绪**（`backend/migrations/` + `docker-compose.postgres.yml`），未来切 SaaS 一行 env 切换

### 决策 4：苏格拉底式对话的"严格度"

- **AI 建议**：Tutor 回答可包含部分知识点
- **学生 C 决策**：**严格执行「只提问不回答」原则**，加 `enforceQuestionOnly()` 函数 + 单测守门
- **理由**：核心教学理念是"逼迫学生自主思考"；任何知识点泄露都削弱教学效果

### 决策 5：代码审查的"安全边界"

- **AI 建议**：exec 用户 Python 代码，捕获异常当审查输入
- **学生 A 决策**：**Python 不执行**，纯静态启发式
- **理由**：学生可能贴恶意代码（`import os; os.system('rm -rf /')`）；**安全 > 准确率**

### 决策 6：代码审查反馈的"非泄题"原则

- **AI 起初**：在 suggestion 字段写完整修正代码
- **学生 A 修正**：`sanitizeNoLeak()` 检测 SELECT/INSERT/UPDATE/DELETE 完整语句，长度 > 40 字符的截断隐藏；prompt 强约束"必须以引导性问句结尾"
- **理由**：与 TutorAgent 苏格拉底原则一脉相承；学生要"自己挣到"答案

### 决策 7：教师智能导入的"分类速度"

- **AI 建议**：纯 LLM 分类（精度高但每次 1.5s 延迟）
- **学生 C 决策**：**启发式优先 + LLM 兜底**（启发式覆盖 80% 常见情况，剩下 20% 用 LLM）
- **理由**：教师批量上传 10 个文件时延迟不能接受

### 决策 8：鸿蒙入口的"形态"

- **AI 建议**：写完整 HAP / 元服务
- **学生 D 决策**：仅提供小艺 openapi skill 定义 + ArkTS 壳骨架 + 冒烟脚本
- **理由**：C4 Agent 创新赛不要求 HAP；交付"小艺测试态 Agent"是更聚焦的形态

## 5. AI 局限性观察

- **教学策略设计**：AI 缺乏教育学背景，**无法独立做出"该不该给提示"的判断**；需要学生 C 反复实测课堂反馈
- **跨会话一致性**：AI 在单次交互中表现好，但**容易忘记之前的对话上下文**；需要学生 A 设计 StudentMemory 持久化
- **安全边界**：AI 倾向于"功能全"（如建议 exec Python 代码），学生必须主动约束（"不做 X"）
- **本地化语言**：AI 写中文 prompt 时偶尔会"机翻腔"；学生 C 多轮润色

---

## 6. 总结

1. **AI 是加速器，不是替代品**：模板代码 / 文档撰写效率显著；核心教学算法 / 安全边界 / 教学理念必须手写
2. **人机协同最高效**：AI 出初稿 → 学生审核 → 课堂实测 → 迭代优化
3. **教育领域特殊性**：教学策略设计需要教育学专业知识和实际课堂经验，AI 难以独立完成
4. **诚实边界声明**：所有 AI 生成内容**均标注**；本项目的核心创新（信任分 / 4 Agent / 教师智能导入 / 代码审查）均由学生构思并手写关键代码
