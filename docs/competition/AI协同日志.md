## 二、AI 辅助开发日志

### 阶段 1：需求分析与架构设计

| 日期 | AI 使用记录 | 人工参与 |
|------|-----------|---------|
| 第 1 周 | 通过 AI 辅助梳理《数据库原理》课程的教学痛点，讨论"信任分"机制的可行性 | 教师确定最终需求范围，选定苏格拉底式教学法作为核心理念 |
| 第 2 周 | AI 辅助设计数据模型（User / Class / Course / Lesson / Homework），给出初始 ER 图建议 | 团队评审并修改数据模型，增加 HomeworkAttempt、LearningSession 等实体 |

**人工修改比例**：约 60%。AI 提供的初始架构方案需要大量调整以适配实际教学场景。

### 阶段 2：后端开发

| 日期 | AI 使用记录 | 人工参与 |
|------|-----------|---------|
| 第 3–4 周 | AI 辅助生成 Go HTTP Handler 模板代码，包括 CORS 中间件、JSON 编解码工具函数 | 手动实现核心业务逻辑：信任分计算、四大 Agent 策略、RBAC 权限控制 |
| 第 5–6 周 | AI 辅助实现 SQLite 存储层，生成建表 SQL 和基础 CRUD 方法 | 手动实现复杂查询（分页、关联查询）、数据迁移逻辑、并发安全处理 |
| 第 7–8 周 | AI 辅助设计 Agent Prompt，讨论 TutorAgent "只提问不回答"的提示词策略 | 多轮迭代调优 Prompt，结合实际教学场景测试效果 |

**人工修改比例**：约 50%。AI 生成的模板代码直接可用，但核心业务逻辑（信任分、Agent 策略、RAG 检索评分）均为手动实现。

**典型交互示例**：

```
问：设计一个信任分计算公式，综合考虑学生的提问质量、解释能力和反思深度

AI 建议：
  信任分 = 提问质量×0.33 + 解释能力×0.33 + 反思深度×0.34

团队调整：
  信任分 = 提问质量×0.45 + 解释能力×0.35 + 思维深度×0.20
  
调整原因：在实际教学中，学生的解释能力比提问质量更能体现真正理解程度，
  但信任分还需要区分"提问质量"和"思维深度"两个维度。
  最终权重经过多轮实际课堂测试后确定。
```

## 三、AI 生成代码的采纳统计

| 代码模块 | 总行数（约） | AI 生成占比 | AI 代码采纳率 | 说明 |
|----------|-----------|-----------|-------------|------|
| HTTP Handler（handlers.go） | 620 行 | ~70% | 85% | 模板代码生产效率高 |
| 核心业务逻辑（service.go） | 1200 行 | ~30% | 50% | 信任分、Agent 调度等核心逻辑手写 |
| AI Agent 策略（agents.go） | 330 行 | ~40% | 60% | Prompt 和 fallback 逻辑需大量调优 |
| 信任分引擎（trust.go） | 60 行 | ~20% | 40% | 核心算法完全手写 |
| RAG 检索（retrieval.go） | 150 行 | ~35% | 55% | 评分规则手动设计 |
| 数据类型（types.go） | 475 行 | ~60% | 80% | 结构体定义效率高 |
| 前端组件 | ~2000 行 | ~50% | 65% | 骨架代码采纳率高，UI 细节手工调整 |

**整体统计**：AI 参与生成约 45% 的代码，其中约 65% 被直接或修改后采纳。

## 四、关键设计决策中的 AI 参与

### 决策 1：信任分分级策略

- **AI 建议**：采用连续分数，不做分级
- **团队决策**：采用四级分级（locked / hint / partial / explain）
- **理由**：离散分级更符合教学直觉，便于教师理解和解释

### 决策 2：Agent Fallback 策略

- **AI 建议**：LLM 不可用时直接返回错误
- **团队决策**：每个 Agent 实现本地启发式 Fallback
- **理由**：教学系统不能因 LLM 故障而完全停止服务，必须保证基础功能可用

### 决策 3：存储引擎选择

- **AI 建议**：直接使用 PostgreSQL
- **团队决策**：JSON 文件 + SQLite 双驱动，可切换
- **理由**：开发阶段 JSON 文件便于调试，生产环境使用 SQLite 性能足够，避免运维 PostgreSQL 的额外成本

### 决策 4：苏格拉底式对话策略

- **AI 建议**：Tutor 回答中可以包含部分知识点
- **团队决策**：严格执行"只提问不回答"原则（enforceQuestionOnly 函数）
- **理由**：核心教学理念是逼迫学生自主思考，任何知识点泄露都会降低教学效果

---

## 五、总结

1. **AI 是加速器，不是替代品**：AI 在模板代码生成、文档撰写等重复性工作中效率显著，但核心教学算法和策略设计均需团队深度参与。
2. **人机协同最高效**：AI 生成初稿 → 团队评审修改 → 实际测试验证 → 迭代优化，形成高效的协作循环。
3. **教育领域的特殊性**：教学策略的设计需要教育学专业知识和实际课堂经验，AI 难以独立完成。
