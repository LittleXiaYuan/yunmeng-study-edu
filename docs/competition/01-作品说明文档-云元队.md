## 1. 一句话创意 + 痛点

一句话创意：

> 云元是鸿蒙场景下的沉浸式 AI 伴学 Agent：用信任分决定只提问、给提示还是讲思路，教师侧可智能筛选教案入库，把 AI 从答案机变成会把握分寸的课程伙伴。

痛点：

- 学生基础差异大，教师难以及时提供个性化指导
- 通用大模型容易变成"答案机"，削弱学生的思考过程
- 教师零散资料难以系统化，知识库检索困难
- 学习过程缺乏正向反馈与分层引导

一句话创意 + 痛点配合鸿蒙 Agent 入口与全场景延展，是产品价值与竞争点所在。

## 2. 需求与用户

### 2.1 教师视角

- 诺课《数据库原理》教师：
  - 需将线下/自有资料整理为课程知识库
  - 需快速了解各班级掌握情况与共性问题
  - 希望大模型不直接给答案，而是在恰当时机给出提示与引导
- 超管视角：
  - 管理多校多班级，统一管控账号与数据隔离
  - 确保系统安全、稳定、可扩展

### 2.2 学生视角

- 学生小张，基础中等：
  - 需要有人提醒时间与作业进度
  - 需要针对性提示，而不是直接答案
  - 希望教练能根据当前作业与错误，给出渐进式引导

### 2.3 鸿蒙场景视角

- 鸿蒙全场景入口：
  - 小艺对话 / 通知 / 主动服务技能
  - PC、穿戴等设备推送作业提醒与错题难点引导

## 3. 核心创新 1：信任分门控

### 3.1 信任分定义

综合提问质量、解释与反思深度，将辅导权限分为四级：

| 等级 | 分数范围 | 典型行为 |
|------|----------|----------|
| locked | <30 | 只提问、不讲解、不示例 |
| hint | 30–59 | 可提供提示与反问 |
| partial | 60–79 | 可进行部分讲解与简单类比 |
| explain | ≥80 | 可完整讲解思路 |

### 3.2 信任分触发条件（示例）

- 第一次作业提问：locked
- 正确完成 2 次提示式引导后：hint
- 正确完成教案概念检索与实践题并反思：partial
- 正确完成综合题并提交反思草稿：explain

### 3.3 鸿蒙入口联动

- 小艺对话中，同一会话仅在信任等级提升后增大提示深度
- 鸿蒙多设备上，超管侧可对单用户强制降级以防范作弊

## 4. 核心创新 2：教师侧智能导入

### 4.1 真文件上传机制

- 对话区支持挂 zip/docx/pdf 名单文件
- 后端解析后返回导入报告卡
  - 已入库：教案/练习 / 触发签名概念抽取
  - 噪声：花名册、课程大纲等自动跳过并说明理由
  - 列表：批量建班/导入学生名单的可视化结果

### 4.2 意图识别与过滤

- 文件类型 → 教案/练习/噪声/名单
- 教案文件名/内容关键词 → 识别与课程关联度高的部分
- 同一概念出现多次 → 去重，避免知识库冗余

### 4.3 导入报告与知识库

- 导入报告展示入库内容摘要
- 学生问答时对应知识点可被引用与检索
- 鸿蒙 Agent 可通过小艺技能直接检索老师上传的资料

## 5. 核心创新 3：学生教练「看见屏幕」

### 5.1 page_context 全场景覆盖

- 题干呈现、阶段选择、草稿与答题页
- 教练读取当前上下文：题干、选项、已弹思路、阶段标签
- 引导不空泛，基于当前题目与阶段生成具体化提问

### 5.2 只引导不泄题

- 信任等级 locked 时：只提问、示例
- trust 提升：出现提示短语与错题方向提示
- 不自动写出答案与完整代码

### 5.3 引用课程资料

- 可调用知识库片段，给出对应章节引用
- 鸿蒙端以卡片形式展示简明结论与引用链接

## 6. 多 Agent 教学闭环

### 6.1 四 Agent 职责

| 角色 | 核心职责 |
|------|----------|
| Teacher（解析） | 解析课程教案、知识点语义与关联 |
| Tutor（伴学） | 基于当前题目与阶段，逐步引导与反问 |
| Evaluator（评价） | 综合作业正确率/反思深度，维护信任分 |
| Reflector（汇总共性） | 为教师生成班级共性错误与教学内容建议 |

### 6.2 本地优先与降级

- 多 Agent 协作逻辑保留在本地服务
- 若大模型中断，前端挖坑与兜底提示保证不空屏
- 鸿蒙端统一 Agent 接口，本地策略可替换为远程 LLM

## 7. 系统架构

### 7.1 鸿蒙入口与复用

- 小艺 Agent：自然对话与主动服务技能入口
- HAP/元服务：PC 与穿戴设备上的对话与通知入口
- 复用同一智能伴学策略与服务后端

### 7.2 云元服务架构简述

- 外部入口：小艺/前端/鸿蒙壳
- 接网关：鉴权、学校隔离、信任分门控中间件
- 战略层：伴学策略与多 Agent 协作逻辑（本地）
- LLM 适配层：大模型调用与本地降级
- 数据层：用户/学校/班级/课程/作业/会话/知识库

## 8. 平台能力

### 8.1 组织模型

- 学校 → 班级 → 课程 → 用户（教师/学生）
- 超管可管理学校列表、重置账号、查看全局报表
- 教师仅可管理自己授课班级与课程

### 8.2 数据隔离

- 学校级别租户划分
- 会话与会话上下文绑定班级与课程
- 超管后台仅配置与统计，不接触具体业务数据

## 10. 测试与质量

### 10.1 单元测试覆盖

- `go test ./internal/edu_service/ -count=1`：
  - 学校管理仅超管访问
  - 跨班导入被拒
  - 旧数据学校迁移回填

### 10.2 隔离矩阵

| 用户角色 | 学校管理 | 跨班导入 | 跨课导学 | 信任分维护 | 导入报告 |
|----------|----------|----------|----------|------------|----------|
| admin    | 可       | -        | -        | -          | -        |
| teacher  | 不可     | 不可     | 本班可   | 可         | 含本班   |

## 11. 鸿蒙落地

### 11.1 小艺 Agent 入口

- 以对话为主要入口（语义理解 + 主动服务）
- 作业提醒、错题引导、复习通知等可按日程主动推送到鸿蒙设备
- 小艺技能可用态（测试态）已交付

### 11.2 鸿蒙灰度与规划

- 后续可接入鸿蒙元服务、车机语音、穿戴提醒等
- Panel 渲染下沉至鸿蒙侧，云元策略复用

## 12. 应用前景与推广

### 12.1 适用场景

- 《数据库原理》《操作系统》等理科课程
