# 第二部分：项目概况

## 一、项目背景与问题定义

在高校《数据库原理》课程教学中，存在三大核心痛点：

1. **学生认知差异大**：同一课堂中学生的理解程度参差不齐，教师难以实现个性化指导。
2. **教学反馈滞后**：传统作业批改周期长，教师无法及时发现学生的理解偏差和思维误区。
3. **深度学习不足**：学生习惯性"要答案"，缺少解释、反思、举例等高阶认知训练。

## 二、解决方案

本项目构建了一个**数据驱动的人机协同教学闭环系统**，核心创新在于：

- **四大 AI Agent 协作**：TeacherAgent（教案解析）、TutorAgent（苏格拉底式辅导）、EvaluatorAgent（多维评估）、ReflectorAgent（教学反思），形成"教→学→评→反思"完整闭环。
- **信任分机制（Trust Score）**：根据学生的提问质量、解释能力和反思深度动态计算信任分，按分数等级差异化控制 AI 回答策略——不直接给答案，逐步引导学生自主思考。
- **RAG 教案检索**：基于教案库的检索增强生成，让 AI 辅导基于课程实际内容回答，而非泛泛而谈。
- **学生画像持久化**：记录每位学生的知识薄弱点、常见错误、思维风格，实现跨会话的个性化辅导。

## 三、系统架构总览

系统采用前后端分离架构，分为三层：

**前端层**：

- 教师端（React + TypeScript + Vite + Tailwind CSS），端口 5175
- 学生端（UniApp），端口 5174

**后端服务层**（Go 标准库 net/http），端口 18080：

- 路由层：30+ RESTful API 接口
- 中间件链：CORS → API Token Auth → Session Auth → RBAC
- 业务逻辑层：核心教学服务
- AI Agent 层：四大教学 Agent（均有 LLM + 本地 Fallback 双路径）
- 辅助引擎：RAG 检索引擎、信任分引擎、学生画像引擎
- 数据持久层：JSON 文件 / SQLite 双驱动（环境变量切换）

**外部服务层**：

- LLM 服务（DeepSeek 等），通过 OpenAI-compatible API 调用

**架构图（文字描述）**：

教师端和学生端通过 HTTP REST API 与 Go 后端通信。后端接收请求后经过 CORS、Token 认证和 RBAC 权限校验，进入业务逻辑层。业务逻辑层调度四大 AI Agent 完成教案解析、辅导对话、学习评估和教学反思。Agent 优先通过 LLM 服务获取结果，LLM 不可用时自动降级到本地启发式算法。RAG 引擎在教案库中检索相关内容，信任分引擎动态计算学生的信任等级，学生画像引擎持久化学生的学习特征。所有数据通过 SQLite（生产）或 JSON 文件（开发）存储。

# 第四部分：技术创新点

## 创新点一：信任分驱动的差异化教学

传统 AI 辅导系统是"问什么答什么"的单一模式。本系统首创 Trust Score 信任分机制：

**计算公式**：信任分 = 提问质量(45%) + 解释能力(35%) + 思维深度(20%)

**四级分级策略**：


| 信任等级    | 分值范围     | AI 策略         | 教学理念      |
| ------- | -------- | ------------- | --------- |
| locked  | 0–29 分   | 只追问，不给任何提示    | "先证明你在思考" |
| hint    | 30–59 分  | 允许提供方向性提示     | "给你一个线索"  |
| partial | 60–79 分  | 允许提供部分答案      | "你已理解大半"  |
| explain | 80–100 分 | 允许提供完整解释与迁移任务 | "你已证明理解"  |


学生必须通过自主思考提升信任分，才能获得更多 AI 帮助。这模拟了真实教学中"先证明你理解了，老师才会帮你更多"的教育逻辑。

## 创新点二：多 Agent 教学闭环

系统采用四个专门化 AI Agent 协作，而非单一大模型直接回答：

1. **TeacherAgent**：解析教案，提取知识图谱（concepts / difficulties / learning_path）
2. **TutorAgent**：元认知学习教练，严格执行"只提问不回答"的苏格拉底式教学
3. **EvaluatorAgent**：7 维度学习评估（理解分、真正理解、错误类型、思维深度、反思水平、提问质量、解释质量、反思深度）
4. **ReflectorAgent**：聚合班级数据，生成教学反思报告和策略建议

关键设计：每个 Agent 均有 LLM 调用 + 本地 Fallback 双路径，确保 LLM 不可用时系统仍可正常运行。

## 创新点三：RAG 增强的课程适配

AI 辅导不是基于通用知识的泛泛回答，而是通过检索增强生成（RAG）机制工作：

- 教师上传教案时，TeacherAgent 自动提取知识点并建立索引
- 学生提问时，RAG 引擎在教案库中检索最相关的课程资料
- 检索结果通过加权评分排序（标题匹配 60 分 + 概念匹配 45 分 + 内容匹配 35 分 + 词项匹配）
- Top-K 相关教案内容注入 TutorAgent 的对话上下文

这确保了 AI 辅导始终基于教师实际讲授的内容，而非 LLM 的通用训练知识。

## 创新点四：分步作业与过程性评价

区别于传统"题目→答案"模式，系统将作业拆分为三个认知阶段：

1. **先说想法**：用自己的话解释核心概念（考察理解深度）
2. **再举例子**：结合熟悉场景举例说明（考察迁移能力）
3. **最后检查**：主动指出学习中容易出错的地方（考察元认知反思）

每个阶段独立评估，学生必须通过当前阶段（理解分 ≥ 65 且解释质量 ≥ 55）才能进入下一阶段。整个过程记录学生完整的思考轨迹，实现真正的过程性评价。

# 第五部分：数据要素应用

## 一、教学数据要素的采集与流转


| 数据要素    | 来源                    | 流转方式                                          | 应用价值            |
| ------- | --------------------- | --------------------------------------------- | --------------- |
| 教案知识图谱  | 教师上传的教案文件             | TeacherAgent 提取 → 持久化 → RAG 检索匹配              | AI 辅导基于课程内容精准回答 |
| 学生画像数据  | 每次交互的评估结果             | EvaluatorAgent 评分 → 更新 StudentMemory → 下次交互读取 | 跨会话的个性化辅导策略     |
| 信任分时序数据 | 每次作业/问答评估             | 计算信任分 → 确定 TrustPolicy → 控制 AI 回答深度           | 差异化教学，因材施教      |
| 多维评估数据  | EvaluatorAgent 7 维度评分 | 每次评估 → 聚合分析 → 班级报告                            | 精准识别知识薄弱点和思维误区  |
| 班级聚合数据  | ReflectorAgent 分析     | 汇总全班学生画像 → 生成共性问题 → 提出策略建议                    | 数据驱动的教学决策       |
| 审计日志    | 全系统操作记录               | 每个写操作 → AuditLog 记录 → 可查询可追溯                  | 教学过程合规与追溯       |


## 二、数据驱动的教学变革

1. **从经验教学到数据教学**：教师不再凭感觉判断学生掌握情况，而是基于多维评估数据做出精准教学决策。
2. **从统一教学到差异教学**：信任分机制让每个学生获得与其认知水平匹配的 AI 辅导策略，实现真正的因材施教。
3. **从结果评价到过程评价**：分步作业记录学生完整的思考过程，而非仅评判最终答案。
4. **从人工反馈到即时反馈**：AI Agent 即时评估学生答案并生成引导性反馈，消除教学反馈时延。
5. **从孤立教学到闭环教学**：四大 Agent 形成"教→学→评→反思"完整闭环，教学数据在闭环中持续积累和优化。

# 第六部分：教育应用价值

## 对教师的价值

- **教案智能化**：一键上传教案，AI 自动提取知识图谱，减少备课工作量
- **精准教学**：基于班级数据分析报告，了解学生共性问题，调整教学重点
- **作业自动化**：AI 一键生成分步作业，自动评估学生答案
- **质量监控**：通过审计日志和学习会话追踪教学质量

## 对学生的价值

- **深度学习**：苏格拉底式追问强制学生思考，避免"伸手要答案"
- **个性化辅导**：AI 根据每位学生的知识画像和信任分提供定制化引导
- **即时反馈**：提交作业即刻获得评估和引导，不需等待教师批改
- **成长可视**：信任分和评估数据让学生看到自己的学习进步轨迹

## 对教学管理的价值

- **数据可视化**：Dashboard 集中展示全班学习状况（平均信任分、平均理解分、共性问题）
- **过程可追溯**：完整的审计日志和学习会话记录
- **可复制推广**：Docker 一键部署，LLM 可配置切换，可快速推广到其他课程和学校

| DeepSeek（运行时 LLM）     | 系统内置 AI Agent 的推理引擎 | 产品运行时组件  |


## 二、分阶段 AI 辅助记录

### 阶段 1：需求分析与架构设计（第 1–2 周）

- **AI 辅助**：梳理教学痛点，讨论信任分机制可行性，设计初始数据模型
- **人工参与**：教师确定最终需求范围，选定苏格拉底式教学法，修改数据模型
- **人工修改比例**：约 60%

### 阶段 2：后端开发（第 3–8 周）

- **AI 辅助**：生成 HTTP Handler 模板代码、SQLite CRUD 方法、Agent Prompt 初稿
- **人工参与**：手动实现信任分计算、Agent 策略逻辑、RAG 评分规则、RBAC 权限、并发安全
- **人工修改比例**：约 50%

**典型协作示例**：

> AI 建议信任分公式：信任分 = 提问质量×0.33 + 解释能力×0.33 + 反思深度×0.34
>
> 团队调整为：信任分 = 提问质量×0.45 + 解释能力×0.35 + 思维深度×0.20
>
> 调整原因：实际教学中，学生的提问质量比反思深度更能体现主动学习态度，权重经多轮课堂测试后确定。

### 阶段 3：前端开发（第 9–12 周）

- **AI 辅助**：生成 React 组件骨架和 TypeScript 类型定义
- **人工参与**：UI/UX 交互设计、样式调整、状态管理、动效实现
- **人工修改比例**：约 45%

### 阶段 4：测试与部署（第 13–14 周）

- **AI 辅助**：Dockerfile、docker-compose.yml、冒烟测试脚本
- **人工参与**：容器化调试、核心测试用例编写、Agent 降级逻辑测试
- **人工修改比例**：约 40%

### 阶段 5：文档与参赛（第 15–16 周）

- **AI 辅助**：项目申报书初稿、README、API 文档
- **人工参与**：审核修改，确保准确反映实际情况
- **人工修改比例**：约 55%

## 三、AI 代码采纳统计


| 代码模块        | 总行数     | AI 生成占比 | 采纳率 |
| ----------- | ------- | ------- | --- |
| HTTP 路由处理   | ~620 行  | ~70%    | 85% |
| 核心业务逻辑      | ~1200 行 | ~30%    | 50% |
| AI Agent 策略 | ~330 行  | ~40%    | 60% |
| 信任分引擎       | ~60 行   | ~20%    | 40% |
| RAG 检索      | ~150 行  | ~35%    | 55% |
| 数据类型定义      | ~475 行  | ~60%    | 80% |
| 前端组件        | ~2000 行 | ~50%    | 65% |


**整体**：AI 参与生成约 45% 的代码，其中约 65% 被直接或修改后采纳。

## 四、关键设计决策中的人机协作


| 决策       | AI 建议          | 团队最终决策            | 人工判断理由           |
| -------- | -------------- | ----------------- | ---------------- |
| 信任分分级    | 连续分数，不做分级      | 四级离散分级            | 离散分级更符合教学直觉      |
| Agent 容错 | LLM 不可用时返回错误   | 本地 Fallback 双路径   | 教学系统不能因 LLM 故障停服 |
| 存储引擎     | 直接用 PostgreSQL | JSON + SQLite 双驱动 | 降低运维成本，开发便利      |
| 对话策略     | Tutor 可包含部分知识点 | 严格"只提问不回答"        | 核心教学理念不可妥协       |


## 五、总结

AI 是加速器而非替代品。模板代码生成和文档撰写中 AI 效率显著，但核心教学算法（信任分、Agent 策略、RAG 评分）和教学设计决策均需团队深度参与。人机协同的最佳模式是：AI 生成初稿 → 团队评审修改 → 实际测试验证 → 迭代优化。
